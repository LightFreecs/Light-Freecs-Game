Namespaces: `LightMMORPG.Core`, `LightMMORPG.<Folder>`, `LightMMORPG.EditorTools`.

**Scenes and prefabs are generated by code** (`ProjectBuilder`) because sessions cannot click in the Unity editor.
Builders must be idempotent (re-running overwrites generated assets). Each builder step is its own static method, and
`BuildAll()` calls them in order: `BuildArt()` → `BuildConfig()` → `BuildPrefabs()` → `BuildArenaScene()` → `BuildMainMenuScene()` → `ConfigureBuildSettings()`.
Later sessions add to `ProjectBuilder` rather than writing a second builder.

## Gameplay rules (prototype)
- Stats: MaxHP 1000, MaxEnergy 100, energy regen 4/s, charge (hold) +30/s while standing still.
- Movement: run 8 m/s, sprint 13 m/s, jump; flight toggle (fly up/down, no gravity, 11 m/s); dash (burst 25 m/s for 0.18 s, 0.6 s cooldown);
  flash step (instant ~7 m teleport in move dir, 2.5 s cooldown). All tick-based inside prediction.
- Melee: 4-hit light combo (damage 30/30/40/60, combo window 0.6 s after each hit, last hit knockback), heavy attack
  (110 dmg, launch/knockback, 1.2 s cooldown). Hit = sphere overlap 1.2 m radius at 1.3 m in front of attacker, server side.
- Block: hold, movement x0.35, blocks 80% damage, guard meter 100 drains by blocked damage/2, at 0 → guard break (stun 1.0 s).
- Hitstun: 0.35 s light, 0.6 s heavy/knockback. Stunned players cannot act.
- Powers (data-driven `AbilityDefinition` ScriptableObjects):
  1. **Energy Blast** — 10 energy, 0.35 s cd, 45 dmg, projectile 40 m/s, radius 0.4, life 2 s.
  2. **Charged Beam** — hold to charge up to 1.5 s, cost 35 energy, dmg 150→400 by charge, spherecast radius 1 m, range 40 m, 4 s cd.
  3. **Power Surge** — 50 energy, 10 s duration, +35% damage, +20% speed, energy regen paused, aura VFX, 20 s cd.
- KO at 0 HP → down for 5 s → respawn at a spawn point with full HP/energy. Scoreboard: KOs / deaths per player.

## Networking model (FishNet)
- Server authoritative. Host mode for local testing; dedicated server when `Application.isBatchMode` or `UNITY_SERVER`
  (auto `ServerManager.StartConnection()` on port 7770). Transport: Tugboat (`FishNet.Transporting.Tugboat`).
- Player spawn: FishNet `PlayerSpawner` (`FishNet.Component.Spawning`, serialized `_playerPrefab`, public `Transform[] Spawns`).
  Networked prefabs must be in `Assets/DefaultPrefabObjects.asset`; after creating prefabs call
  `FishNet.Editing.PrefabCollectionGenerator.Generator.GenerateFull(null, true)` (check exact namespace in
  `Packages/com.firstgeargames.fishnet/Runtime/Editor/PrefabCollectionGenerator/Generator.cs`, class is internal — if not
  accessible, rely on its AssetPostprocessor by importing the prefab with `AssetDatabase.ImportAsset`, or register via SerializedObject).
- **Movement = client-side prediction**, copy the pattern from
  `Packages/com.firstgeargames.fishnet/Demos/Prediction/CharacterController/Scripts/CharacterControllerPrediction.cs`:
  - derive from `FishNet.Utility.Template.TickNetworkBehaviour`, `SetTickCallbacks(TickCallback.Tick | TickCallback.PostTick)`.
  - `struct ReplicateData : IReplicateData` (move Vector2, camera yaw float, sprint/fly-up/fly-down/block/charge bools,
    one-time inputs jump/dash/flashStep/toggleFlight, `private uint _tick; GetTick/SetTick/Dispose`).
  - `struct ReconcileData : IReconcileData` (position, vertical velocity, flying, dash timer, cooldown timers,
    knockback velocity, stun timer).
  - `[Replicate] void PerformReplicate(ReplicateData rd, ReplicateState state = ReplicateState.Invalid, Channel channel = Channel.Unreliable)`
  - `[Reconcile] void PerformReconcile(ReconcileData rd, Channel channel = Channel.Unreliable)` — disable CharacterController before setting position.
  - Use `(float)TimeManager.TickDelta` inside replicate. Build inputs only `if (IsOwner)`; accumulate one-time inputs in `Update`.
  - Server-applied effects (knockback, stun, respawn teleport) are written into the motor's state on the server; reconcile corrects the client.
- NetworkObject on the player: `_enablePrediction = true`, `_predictionType = Other`, `_graphicalObject` = child "Graphics"
  (visual mesh) so FishNet smooths it. Set via `SerializedObject` in the builder.
- Combat actions (light/heavy/blast/beam/surge) = owner `[ServerRpc]` with aim direction → server validates (cooldown,
  energy, stun, alive), resolves hits, applies damage → `[ObserversRpc]` to play anim/VFX on all clients.
  Owner may play its own swing/VFX immediately (`ExcludeOwner = true` on the observers RPC in that case).
- Projectiles are **not** network objects: server simulates the authoritative projectile and resolves hits; clients
  spawn a visual-only copy from an ObserversRpc (origin, direction, speed).
- Synced state uses FishNet v4 SyncVars: `private readonly SyncVar<float> _hp = new();` with `.Value` and
  `.OnChange += (prev, next, asServer) => ...`. Attributes: `[ServerRpc]`, `[ObserversRpc]`, `[TargetRpc]`, `[Server]`.
- No lag compensation in this milestone (generous hitboxes instead). Note as a later improvement.

## Input
- Built in code (no .inputactions asset needed): `InputAction`s with keyboard/mouse + gamepad bindings.
  PC: WASD move, mouse look, Shift sprint, Space jump/fly up, Ctrl fly down, F toggle flight, Q dash, E flash step,
  LMB light, RMB heavy, R block (hold), C charge (hold), 1 Energy Blast, 2 Charged Beam (hold+release), 3 Power Surge, Tab lock-on.
- Mobile: runtime-built uGUI overlay (virtual joystick left, drag-to-look right half, action buttons) writes into a static
  `TouchInputState`; the player input reader merges it with Input System values. Shown when `Application.isMobilePlatform`
  or `Touchscreen.current != null`.

## Visual style
- Custom URP shader `LightMMORPG/ToonLit`: 2–3 band ramp from main light (with shadows), shadow tint color, rim light,
  outline pass (inverted hull, `Cull Front`, tag `"LightMode"="SRPDefaultUnlit"`), ShadowCaster + DepthOnly passes,
  SRP-batcher compatible (`CBUFFER_START(UnityPerMaterial)`).
- `LightMMORPG/AuraAdditive`: unlit additive fresnel for aura/beam glow. Bloom via a global Volume.
- Placeholder fighters: capsule body + sphere head + simple procedural animation (lunge/punch, recoil, aura) — no rigs yet.
- Materials and VFX references live in `Resources/GameConfig.asset` (`GameConfig` ScriptableObject) so builds include the shaders.
